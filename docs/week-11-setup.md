# Неделя 11 — первый прототип StudyRadar

Статус: реализованы консольный интерфейс, чтение Canvas и адаптер OpenAI Responses API. Это первая LLM-интеграция; автономный выбор инструментов, Gmail и остальные источники ещё не реализованы. Реальные запросы требуют локальных ключей и отдельной проверки. Офлайн-тесты не доказывают доступ к аккаунтам.

## Запуск

Нужен Python 3.9 или новее с часовыми поясами системы. Внешние Python-библиотеки для этой версии не нужны. Открой Terminal в папке проекта.

```sh
python3 studyradar.py demo
```

Это явно обозначенное синтетическое демо: три вымышленных задания, фиксированное время 9 ноября 2026. Ссылки отражают формат Canvas и не являются реальными заданиями пользователя. Отрицательное число часов означает прошедший срок, а не доказательство невыполнения.

## Локальные ключи

```sh
python3 studyradar.py setup
```

Скрытый ввод сохранит Canvas-токен и OpenAI API-ключ в локальный `.env` с правами 0600. Файл исключён из Git. Если файл уже существует, команда не перезаписывает его. Пустое поле позволяет отложить подключение сервиса. Программа также поддерживает переменные окружения `CANVAS_TOKEN`, `OPENAI_API_KEY`, `LLM_MODEL`.

Canvas-токен для собственного тестового приложения создаётся в Account → Settings → New Access Token, если университет разрешает эту возможность. Для приложения других пользователей нужен соответствующий OAuth-доступ. Проверка наличия кнопки не гарантирует успешный API-запрос.

## Canvas без передачи в модель

```sh
python3 studyradar.py courses
python3 studyradar.py assignments --course 123
```

Замени `123` на ID из списка своих курсов. Можно указать несколько `--course`, максимум пять. Читаются активные курсы и доступные задания выбранных курсов; программы не проверяет всю учебную деятельность. Результат содержит сроки в Asia/Almaty, остаток времени, статус сдачи и ссылки. Не публикуй вывод с личными данными.

Сначала проверь вручную 2–3 результата в Canvas: название, срок и статус. При HTTP 401/403 проверь срок токена и разрешения. Редиректы, сторонние ссылки пагинации, слишком большие ответы и бесконечная пагинация отклоняются. HTML-страница входа не считается успешным ответом API.

## Первый реальный запрос модели

Сначала можно вызвать модель на вымышленных данных (расходует API-кредиты, не читает Canvas):

```sh
python3 studyradar.py ask --demo --question 'Какие задания требуют внимания и где срок неизвестен?'
```

Затем, если разрешаешь передать названия, описания и статусы выбранного курса в OpenAI:

```sh
python3 studyradar.py ask --course 123 --allow-private-data --question 'Что мне нужно сделать первым?'
```

Модель выбирает ID подходящих заданий. Программа проверяет формат, известность и уникальность ID; пояснения статусов, итоговые числа, даты и URL формирует из Canvas. Свободные утверждения модели о задолженности не отображаются. Статус graded без missing=true не считается доказательством долга, даже при пустой дате отправки. Эти проверки не гарантируют истинность каждого предложения модели: рекомендации и выводы нужно оценивать отдельно. Другие сервисы всегда указаны как непроверенные. Calendar пока не изменяется.

## Проверки

```sh
python3 -m unittest discover -s tests/python -v
```

19 тестов проверяют даты, неизвестные сроки, статус graded, пагинацию, запрет отправки токена на другой хост, лимит страниц, некорректные аргументы, обработку HTTP, ответ адаптера, неизвестные/повторные источники и незавершённый ответ модели. Сетевые ответы в этих тестах подменены. Добавлены проверки оценённых, отправленных и освобождённых заданий, явного missing=true и противоречивых статусов. Полные A-level guardrail tests будут добавлены с агентным циклом.
